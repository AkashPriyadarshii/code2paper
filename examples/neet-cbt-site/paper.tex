\begin{abstract}
The repository hosts the static marketing site for the NEET CBT 2027 Simulator, a free,
offline-first progressive web application that replicates the National Testing Agency
(NTA) computer-based test interface for the NEET UG medical entrance examination. The site
is a single-file HTML document (423 lines, 23.5 KB) with embedded CSS and JSON-LD structured
data, deployed via GitHub Pages with no build pipeline. The repository contains 9 files
across HTML, Markdown, XML, plain-text, and raster image assets; source lines total
approximately 455.
\end{abstract}

\section{Architecture \& Component Structure}
The site is a linear one-page document:

\begin{verbatim}
index.html
|-- <head>    primary/OG/Twitter meta + <style> design system
|-- <body>
|   |-- .topbar      - announcement strip
|   |-- header.main  - brand + nav
|   |-- .hero        - headline, lead, dual CTA, stats badges, CSS mock-UI
|   |-- #why         - 4-card rationale grid
|   |-- #features    - 6-feature grid
|   |-- #how         - 3-step + 4-screenshot gallery
|   |-- #faq         - 6-item <details> disclosure
|   `-- footer       - links + NTA trademark disclaimer
`-- 3 x JSON-LD blocks - WebApplication, FAQPage, BreadcrumbList
\end{verbatim}

\begin{itemize}
  \item \textbf{Role:} the entire marketing site.
  \item \textbf{Design system:} CSS custom properties in \texttt{:root} (navy, accent gold, blue, paper), responsive at 820px.

  \item \textbf{Trust architecture:} stat badges, six FAQ disclosures, non-affiliation disclaimer.

Let $F$ be the set of files and $\ell(f)$ the line count of file $f$.

\[ L_{\text{total}} = \sum_{f \in F} \ell(f) = 423 + 17 + 9 + 5 \approx 455 \]

Asset size footprint (bytes):
\[ S = 23{,}479 + 86{,}034 + 70{,}260 + 82{,}508 + 71{,}064 + 330{,}486 \approx 664\text{ KB} \]

Data flow is unidirectional and static: the browser fetches \texttt{index.html} plus
lazily-loaded gallery images; JSON-LD blocks are parsed by crawlers, not executed. No runtime
computation occurs here.

\section{Implementation Trade-offs \& Limitations}
\begin{enumerate}
  \item Single-file simplicity vs.\ maintainability: zero build, zero deps, at the cost of a 423-line file.
  \item Isolation from the product: marketing site and simulator are separate repos.
  \item Static screenshots: WebP captures cannot reflect future UI changes automatically.
  \item Scope: no test suite or CI beyond Pages autodeploy; appropriate for a static page.
\end{enumerate}
